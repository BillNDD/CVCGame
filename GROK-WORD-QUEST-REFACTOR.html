The rule (this is the whole point)

  1. One fact, one owner. A number, a verdict, a sentence a child sees, a gate floor — exactly one document owns it.
  2. One document may own many facts. SPEC.md owns behaviour. CLAUDE.md owns S-rules and E-rules. That is fine.
  3. Everyone else points. If README needs the bank size, it says “see SPEC.md section 3”. It does not write 445. A pointer cannot rot. A copied number can.
  4. Generated files are not owners. voice-lock.json is a machine echo of tools/voice-words.csv. G13 already fails if they disagree. Do not hand-edit echoes.
  5. One index lists the owners. A single document of pointers: fact → owner path. It does not restate the facts. It is the map. A gate fails if (a) a governing file is missing from the map, (b) two rows claim the same fact, (c) a human md restates a mapped fact as a literal instead of a pointer.

Today the repo almost has (1)–(4): F1 headers, G17 file list, G16/G13/G16b checks. It does not have (5). Headers say what a file owns; nothing is the list of all of them in one place, so README can still say 260 while SPEC says 445 and the check stays green.

Call the index docs/OWNERS.md. Owner-approved 2026-08-15 (asked in chat). G17 must name it. It is a document of pointers, not a second SPEC. A stronger form against F3 — generate it from the G17 **This document owns** headers the way G20 generates docs/effect-map.md — is the owner's call. Pass A ships a hand-written docs/OWNERS.md unless the owner picks generate.

7. Pin rules (closes the WAV-from-MP3 hole)

Canonical WAV format when a WAV pin exists:

  • 24000 Hz, mono, signed 16-bit PCM, little-endian, uncompressed WAV
  • pins.wav_sha256 = SHA-256 of the file bytes (header + data)

7.1 Completeness enum

pins.completeness (required):

value Meaning Allowed on locked_heard?
none no audio pins no
mp3_only heard MP3 pinned; no canonical WAV yes, migration grandfather only
wav_only PCM master, no heard MP3 no (cannot be locked_heard)
both WAV + MP3 pins yes (required for new accepts)

7.2 Migration (existing winner MP3)

  1. Copy exact bytes → pins/words/<id>/heard.mp3. Do not transcode.
  2. pins.mp3_sha256 = SHA-256 of that file. If CSV byte_pin_sha256 is non-empty and differs, do not overwrite. Set locked_recipe_only + orphan_reason=csv_pin_disagrees_with_winner_mp3 and record both hashes.
  3. If CSV pin is empty, write the new hash. That is filling a blank, not “updating” a pin.
  4. Do not decode MP3 → WAV and set completeness=both.
  5. Preexisting WAV: copy as master.wav only if (a) TREE-MAP lists that exact path as the word’s WAV and (b) the file already matches §7 canonical format (24 kHz mono s16le uncompressed). Then completeness=both, pins.wav_origin=preexisting_wav. Otherwise do not copy it; leave mp3_only and set legacy.rejected_wav_path. Never resample to satisfy --strict.
  6. Otherwise completeness=mp3_only, legacy.grandfathered_mp3_only=true, pins.wav_relpath="" pins.wav_sha256="".

7.3 New accepts (after this refactor)

accept_asset.py requires completeness=both. --allow-mp3-only is removed — it made “new accepts need both” unenforceable in CI.

Sounds/stitches: constituents + assembled master.wav + copy of owner-heard MP3. WAV-only (no heard MP3) cannot be locked_heard.

accept_asset.py sets legacy.accepted_utc (ISO-8601 UTC). Only that tool may set it.

7.4 MP3 policy

pins.mp3_policy must be "byte_pin". Re-encoding may sound the same and is still a fail if it replaces the pin.

7.5 Pin storage (TREE-MAP git_lfs_for_audio)

TREE-MAP What to do
LFS already used for audio git lfs track 'pins/**' and commit pins through LFS
LFS not used and pins/ ≤ 80 MB commit pin bytes in git
LFS not used and pins/ > 80 MB gitignore pins/ and attach/cache the release zip in CI so verify can read the bytes

Always: refuse to hash a file whose first line is version https://git-lfs.github.com (unsudged pointer). Run git lfs smudge / git lfs pull first.

SHA256SUMS in each pin dir is a convenience copy of pins.* hashes. Verify pins JSON vs file bytes. If SHA256SUMS exists and disagrees, fail. If it is missing, do not fail.

D: is a best-effort mirror after a successful local verify. Never the only CI source.

12. Tools — CLI, exit codes, warn vs fail

12.1 verify_assets.py

python tools/verify_assets.py [--root PATH] [--strict] [--write-index]
                              [--pack-manifest PATH]

Always fail (exit 1):

  • schema invalid
  • index.json missing or stale vs glob of assets/**/*.json (compare asset list + hashes, not a wall-clock field)
  • locked_heard and mp3 file missing or SHA mismatch
  • locked_heard and completeness=both but WAV missing / wrong format / SHA mismatch
  • locked_heard and completeness not in mp3_only|both
  • legacy.grandfathered_mp3_only=true and legacy.accepted_utc is set
  • stitch locked_heard missing constituent file/SHA
  • --pack-manifest (game pack id list) contains an id with status ≠ locked_heard
  • recipe elongate / bake path names a forbidden GPL tool
  • hop/margin when is_new_lock (below)

Historic vs new (one predicate):

  • is_migrated_row = legacy.csv_row_ref non-empty and legacy.accepted_utc empty
  • is_new_lock = legacy.accepted_utc non-empty, or (csv_row_ref empty and status is locked_heard / being accepted)

Hop (asr + head_trim_ms>0) or energy_margin_ms>150: warn if is_migrated_row; fail if is_new_lock.

Energy-cut > 60% of carrier: skip on verify (do not decode MP3 to measure). Fail on accept only if bake output is in hand and measurable.

Warn, do not fail --strict: hop/margin on migrated rows; missing WAV on mp3_only grandfather.

--strict = CI: fail the Always-fail list only.

Must never rewrite a SHA to pass. Do not hash git-LFS pointer files (§7.5).
